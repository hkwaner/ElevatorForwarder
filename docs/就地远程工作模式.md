# 就地 / 远程 工作模式说明

> 本文档独立说明转发器(电梯代理服务)的"就地/远程"工作模式：两种模式的行为差异、切换指令、广播字段、实现细节与联调建议。
> 对外对接方主要关注 [切换指令](#切换指令) 与 [广播字段](#广播字段)；内部开发维护关注 [实现说明](#实现说明)。

---

## 1. 概述

电梯代理服务负责中转并处理其他程序与电梯之间的信息。为同时兼顾**远程调度**和**现场人工操作**两种场景，服务提供"就地/远程"两种工作模式：

- **远程 REMOTE(默认)**：服务全程物理独占电梯，保证机器人/平台可稳定远程控制。
- **就地 LOCAL**：服务释放物理独占，把手动选层权交回现场受控面板，供现场人工操作。

两者通过网页端下发一条 MQTT 指令完成切换，并实时体现在状态广播的 `workMode` 字段上。

---

## 2. 两种模式行为对比

| 维度 | 远程 REMOTE | 就地 LOCAL |
|---|---|---|
| 物理独占 | 启动即独占，每 5 秒无条件续占，防电梯约 1 分钟超时自动释放 | 立即主动释放并停止续占，现场受控面板可用 |
| 远程控制指令(独占/选层/进电梯/出电梯/候梯点) | 正常执行 | **全部拒绝**，并返回"当前为就地模式,远程控制不可用" |
| 卡住自动检测/重试/跨层 | 开启 | **关闭**，不主动干预,避免干扰现场人工 |
| 逻辑占用(`occupiedUser`) | 由机器人 OCCUPY/RELEASE 管理 | 切换时一并清空 |
| 状态广播(含 `workMode`) | 实时广播 | 仍实时广播,便于查看现场情况和当前模式 |
| 重启后 | 默认回到远程 | — 掉电不记忆就地状态 |

> 就地模式下服务仍然是"观察者"：持续接收并广播电梯状态，只是不再主动控制。

## 3. 切换指令

### 3.1 消息体

```json5
{
  "type": "ELEVATOR_CONTROL",
  "action": "SWITCH_WORK_MODE",
  "target": "elevator_proxy",
  "value": "{\"mode\":\"LOCAL\"}",  // mode: "REMOTE"(远程) 或 "LOCAL"(就地)
}
```

- 由**网页端(管理端)** 下发，订阅  `topic-elevator`。
- **设备级管理指令**：不校验逻辑占用权限，任意方可切换，无需先占用电梯。
- `mode` 值不合法或 value 解析失败时，返回 `RESULT_FAIL` 并提示。

### 3.2 返回

返回参考通用 `RESULT` 示例：成功时 `value` 提示当前模式（如"切换工作模式成功!当前为就地模式,远程控制不可用"）。

### 3.3 切换时的联动动作

| 切换到 | 执行动作 |
|---|---|
| **就地 LOCAL** | ① 清空逻辑占用 `occupyUserInfo=null`；② 向电梯发送物理释放指令(`A0 00 02 00`)；③ 置 `occupyEnabled=false` 停止 5 秒续占；④ 置 `workMode=LOCAL` |
| **远程 REMOTE** | ① 置 `occupyEnabled=true` 并立即发送物理占用指令(`A0 00 12 00`)恢复独占；② 恢复所有远程控制与自动重试；③ 置 `workMode=REMOTE` |

## 4. 广播字段

状态广播 `value` 中的电梯消息(JSON)新增字段 `workMode`：

```json5
{
  // ...既有字段...
  "occupiedUser": "429370_Y_1000000_...",   // 独占用户id,就地模式为null
  "occupiedUserName": "张三",                // 独占用户名称,就地模式为null
  "workMode": "REMOTE",                     // REMOTE(远程)/ LOCAL(就地)
}
```

- 网页端依据 `workMode` 判断当前**是否可远程控制**，并决定是否展示切换入口。
- 就地模式时 `occupiedUser/occupiedUserName` 为 `null`。

### 4.1 电梯状态信息广播 · 字段全集

广播由 `MqttManager.broadcastElevatorResult` 通过 `Gson.toJson(elevatorResult)` 序列化**整个 `ElevatorResult` 对象的全部非 `transient` 字段**。以下为真实广播的字段及其语义，与当前代码一致（2026-09 核对）：

```json5
{
  "originalData": [-96, 1, 0, 0, 10, -45], // 电梯返回的原始6字节报文(转成带符号十进制)
  "receiveTime": 1776656531422,            // 消息接收时间(毫秒时间戳)
  "isLeveling": false,                     // 轿厢是否在平层
  "floor": 0,                              // 轿厢停靠楼层(仅平层有效,运行中/不再平层为0)
  "isMovingUp": true,                      // 是否上行中
  "isMovingDown": false,                   // 是否下行中
  "isMoving": true,                        // 是否运动中(三个运动位任一为真即真)
  "status": "上行中",                       // 状态文本: 正常/运动中/上行中/下行中/独占异常/故障码(十六进制)
  "occupiedUser": null,                    // 当前逻辑占用用户id,没人占用为null
  "occupiedUserName": null,                // 当前逻辑占用用户名称,多人占用为null
  "workMode": "REMOTE",                    // 工作模式: REMOTE(远程)/ LOCAL(就地)
  "isElevatorNormal": true                 // 电梯是否正常(data1==0x00);异常时 status即故障码
}
```

字段语义说明：

| 字段 | 类型 | 语义 |
|---|---|---|
| `originalData` | int[] | 原始报文，`[0]设备标识 0xA0 [1]data0(楼层/运动) [2]data1(状态) [3]data2(机器人独占地址) [4]data3保留 [5]CRC校验` |
| `receiveTime` | long | 收到该帧的毫秒时间戳 |
| `isLeveling` | bool | data0 低5位为0(不在平层)时 false |
| `floor` | int | 低5位楼层值；仅当 `isLeveling` 时才有效(0 表示不在平层)，"运行中会为0" |
| `isMovingUp / isMovingDown` | bool | data0 第5/6位 |
| `isMoving` | bool | data0 第7位 或 上/下行任一为真 |
| `status` | string | data1：`0x00`→正常(运动中依次优显 运动中/上行中/下行中)；`0xFF`→独占异常；其余→该字节十六进制故障码 |
| `occupiedUser / occupiedUserName` | string|null | 由 `LogicHandler` 逻辑占用填充，无人占用为 null；就地模式必为 null |
| `workMode` | string | `REMOTE` 或 `LOCAL` |
| `isElevatorNormal` | bool | data1==0x00 |

> **不参与广播的字段**（`transient`，前端勿依赖）：`receiveTimeNano`(纳秒内部用)、`isOccupiedError`(独占异常内部判断)、`isOccupiedSuccess`(是否完成独占内部判断)。是否完成独占请以 `data2` 最高位(`0x80`)为准（对应 `originalData[3]`）。

## 5. 就地模式的详细行为

1. **物理释放**：主动发送释放指令，现场受控面板恢复人工选层；续占停止，避免重新抢占。
2. **拒绝远程控制**：`OCCUPY_ELEVATOR / RELEASE_ELEVATOR / SELECT_FLOORS / ENTER_ELEVATOR / EXIT_ELEVATOR / ACTION_TO_WAITING_POINT` 六类指令全部返回失败，提升"当前为就地模式,远程控制不可用"。
3. **关闭自动重试**：`handleStuckDetection` 就地模式下直接返回，不触发卡住检测/跨层。
4. **清空逻辑占用**：切换时就地模式清空 `occupyUserInfo`；切回远程后机器人需**重新发送 `OCCUPY_ELEVATOR`** 才能继续选层。
5. **仍实时广播**：服务继续接收电梯数据并广播，`workMode=LOCAL`，方便网页端查看现场情况及当前模式。
6. **重启默认远程**：模式存于内存(volatile)，掉电/重启后回到远程模式，需要就地时重新切换。

## 6. 实现说明

### 6.1 状态模型

| 状态 | 位置 | 类型 | 语义 |
|---|---|---|---|
| `workMode` | `LogicHandler` | `volatile String` | `"REMOTE"` / `"LOCAL"`，共享读(广播/切换) |
| `occupyEnabled` | `ElevatorConnector` | `volatile boolean` | 物理独占开关，`true`=远程续占，`false`=就地停占 |

### 6.2 切换流程

```
switchWorkMode(mqttMsg)
  ├─ 解析 value.mode
  ├─ 校验 ∈ {REMOTE, LOCAL},否则 RESULT_FAIL
  └─ synchronized(occupyStatusLock):
       ├─ workMode = mode
       ├─ LOCAL → occupyUserInfo=null; ElevatorConnector.setOccupyEnabled(false)  (发释放+停续占)
       └─ REMOTE → ElevatorConnector.setOccupyEnabled(true)                      (发占用+恢复续占)
       └─ RESULT_SUCCESS(提示当前模式)
```

### 6.3 就地时控制消息拦截

六个 `checkXxx` 方法入口处统一 `if (isLocal()) return RESULT_FAIL(…当前为就地模式…)`，早于参数校验与占用校验。

### 6.4 改动文件清单

| 文件 | 改动 |
|---|---|
| `MqttConstants` | 新增 `ACTION_SWITCH_WORK_MODE` |
| `LogicHandler` | 新增 `workMode` 状态、`switchWorkMode()`、就地拦截；`getWorkMode/isLocal/isRemote` |
| `MqttMsgHandler` | switch 增加切换 case |
| `ElevatorConnector` | 新增 `occupyEnabled`、`setOccupyEnabled()`、`sendReleaseCommand()`、`resetOccupyTracking()`；`sendOccupyCommand()` 按开关门控 |
| `ElevatorResult` | 新增 `workMode` 广播字段(convertMsg / asMovingOverride) |
| `ElevatorResultHandler` | 就地时 `handleStuckDetection` 直接返回，关闭自动重试 |

### 6.5 线程安全

- `workMode` 为 `volatile`，切换写、广播读、续占判断读均为可见的单值读写，无需额外同步。
- 切换对 `occupyUserInfo` 的清空放在 `synchronized(occupyStatusLock)` 内，与占用/选层鉴权互斥，避免就地切换与并发控制指令竞争。
- 切换指令与其他控制消息共用 `MqttManager` 的 target 过滤与去重通道，线程模型与既有控制指令一致。

## 7. 联调与验证建议

1. **切换生效**：网页端发 `SWITCH_WORK_MODE` → 收到 `RESULT_SUCCESS`，广播 `workMode` 对应变化。
2. **就地释放**：切就地后模拟器/真梯应收到释放指令，现场面板可人工选层；强占位(占用位)不再续置。
3. **就地拒绝**：就地模式下发送独占/选层，返回失败提示。
4. **重试关闭**：就地模式下人为制造卡住，确认不再触发自动跨层。
5. **切回远程**：切远程后立即收到占用指令，独占恢复；机器人需重新 OCCUPY 才能选层。
6. **重启**：重启后回到远程模式。

---

## 8. 注意事项

- 就地模式下远程控制"不可用"即为预期，勿把它当故障处理。
- 切就地会清空逻辑占用，业务上注意先让机器人完成当前任务再切。
- 当前模式不持久化，重启默认远程；如需掉电记忆可后续扩展(数据库/配置文件)。
